# Крепкий лёд

Карта состояния льда в Амурском и Уссурийском заливах у Владивостока: наблюдения рыбаков, погода,
запреты МЧС, анализ фотографий. Приложение не гарантирует безопасность льда и не оценивает его прочность.

| Компонент | Технология |
|---|---|
| Мобильное приложение | React Native + Expo (SDK 58), Expo Router, TypeScript; работает в Expo Go |
| Карта | Своя: Leaflet + OpenStreetMap в WebView; вода разбита на ячейки H3 от 0,015 до 0,74 км² по береговой линии GSHHG |
| Backend | Python + FastAPI |
| БД | MySQL 8 / MariaDB через SQLAlchemy + PyMySQL |
| Модель 1 | YOLO: лица и автомобильные номера → размытие (запасной вариант: каскады Хаара) |
| Модель 2 | Анализ фото льда: материал, текстура, трещины, вода (компьютерное зрение + ваша модель) |
| Текст | Ollama `qwen2.5:3b` или правила |
| Погода | Open-Meteo |

## Что нового в версии 6

- **Подробная сетка воды.** Берег взят из GSHHG в полном разрешении (около 100 м) вместо маски с шагом 1 км.
  Ячейки разного размера: открытая вода около 0,74 км², у берега около 0,1 км², на реке Раздольной полоса
  ячеек по 65 м. Покрыто 99,2 % воды заливов, все бухты и берега учитываются.
- **Модерация**: фильтр мата, ссылок, телефонов и рекламы; проверка текста локальной моделью; повторные фото;
  жалобы; очередь модератора; блокировки; журнал решений.
- Схема базы изменилась (новые таблицы и поля). Таблицы создаются сами, но в существующие таблицы MySQL новые
  поля не добавляются: **создайте новую пустую базу** или удалите старые таблицы. Наблюдения со старых ячеек
  при запуске сервера переносятся на новые по их координатам.

## Карта: сетка воды

- **Берег и реки**: `backend/data/coast/land.geojson` и `rivers.geojson` — береговая линия GSHHG 2.3
  (полное разрешение, лицензия LGPL) для района Владивостока. В GSHHG есть только крупные реки, здесь это
  Раздольная. Чтобы добавить реку (Артёмовка, Шкотовка и др.), допишите её линию в `rivers.geojson`
  (LineString, координаты `[долгота, широта]`, поле `width_m`) и пересоберите сетку.
- **Сетка**: `backend/data/grid.geojson`, строится командой

```powershell
.venv\Scripts\python tools\build_grid.py
```

  Ячейки — шестиугольники H3: каждая крупная делится на 7 мелких. В открытой воде дальше 300 м от берега
  используются ячейки уровня 8 (~0,74 км²), у берега — уровня 9 (~0,1 км²; ячейка остаётся, если хотя бы 35 %
  её площади — вода), вдоль рек — уровня 10 (~0,015 км²). Сейчас 6651 ячейка: 2285 в открытой воде, 4101 у
  берега, 265 на реке.
- **Передача на телефон**: сервер отдаёт только номера ячеек H3 и их центры (`/grid`, около 280 КБ один раз,
  потом из памяти телефона). Шестиугольники по номерам рисует сама карта: в неё встроена библиотека h3-js.
- **Места** (`backend/data/places.json`) — подписи и точки поиска; запреты действуют на все ячейки в заданном
  радиусе. Места теперь в 200–630 м от своей ячейки (раньше до 1,7 км).
- Статус ячейки считается только по наблюдениям в ней. Пустые ячейки серые: неизвестное выглядит неизвестным.


## Что делает ИИ

ИИ ничего не решает за человека, никогда не пишет, что лёд безопасен, и только повышает уровень опасности.

### Модель 1: лица и номера (`backend/app/anonymizer.py`)

- YOLO-модель `yolo26m_face_lp.pt`: порог уверенности 0,25, рамки расширяются на 25 %, пикселизация плюс
  сильное размытие; для лиц — овальная маска с мягкими краями, для номеров — прямоугольник.
  Это перенос вашего `test_anonymizer.py`.
- Нет файла модели или пакета `ultralytics`, или модель упала — работают каскады Хаара из OpenCV.
  Опубликованное фото никогда не остаётся неразмытым из-за сбоя модели.
- Из файла удаляются все метаданные (GPS, модель телефона). Хранится только обезличенная копия.
- Статус `NO_DETECTIONS` не означает «гарантированно обезличено». Нужны жалобы и модерация.

### Модель 2: лёд на фото (`backend/app/ice_vision.py`)

Два слоя, побеждает более тревожный результат:

1. **Компьютерное зрение без обучения** (всегда, на процессоре, около 50 мс):
   - материал по цвету (HSV) на нижних 70 % кадра: снег, белый лёд, прозрачный (тёмный) лёд, вода;
   - текстура по резкости деталей: гладкая, зернистая, неровная;
   - трещины: тонкие тёмные линии (black-hat фильтр + анализ формы: длинная и тонкая);
   - признаки: «трещина», «вода на льду» (10–35 % воды), «открытая вода» (от 35 %).
2. **Ваша обученная модель** (`models/ice.pt`, любая YOLO классификации или детекции). Названия классов
   превращаются в признаки по ключевым словам: crack → трещина, water/wet → вода на льду,
   hole/polynya/open → промоина, thin → тонкий лёд.

Плюс, если запущена Ollama с моделью зрения (`qwen2.5vl:3b`), она проверяет, есть ли на фото лёд,
и может отклонить явно постороннее фото.

**Ограничения.** Пороги слоя 1 подобраны на синтетических картинках. На реальных фото будут ошибки:
тени похожи на трещины, тёмный прозрачный лёд похож на воду, снег скрывает трещины. Перед тем как
опираться на эти признаки, соберите 50–100 фото из заливов с пометками и проверьте точность. Это же
станет основой для обучения `ice.pt`. Анализ никогда не понижает уровень: «трещин не найдено» не значит
«безопасно».

### Текст и предупреждения

- Текст наблюдения: признаки опасности по ключевым словам или через Qwen. «Без тревог» с текстом
  про трещину считается как «Есть риск».
- Предупреждения по заливам: сервер собирает факты (ветер, потепление, число сигналов), ИИ формулирует.
  Запрещённые слова («безопасно», «выдержит», «можно идти») отбрасываются.
- Скопления: если 2+ разных человека сообщили об опасности в радиусе 200 м за 6 часов, на карте круг
  и предупреждение «Требуется проверка участка».

## Модерация

**Автоматически, при публикации** (`backend/app/moderation.py`):

| Что | Что происходит |
|---|---|
| Мат (корни слов, в том числе с приставками), в тексте и в имени | отклоняется: «Уберите нецензурные слова» |
| Ссылки, телефоны, @ники, t.me | отклоняется: «Ссылки, телефоны и контакты запрещены» |
| Реклама («продам», «казино», «пишите в личку»…) | отклоняется |
| Бессмысленный набор символов | отклоняется |
| Qwen считает текст оскорблением, спамом или не по теме | публикуется «на проверке» |
| Фото, уже загруженное раньше (тем же или другим аккаунтом, в том числе уменьшенное или пережатое) | отклоняется: «Это фото уже публиковалось» (сравнение отпечатков dHash) |

**Жалобы.** Под каждым чужим наблюдением есть «Пожаловаться» (фейк, спам, оскорбления, фото не про лёд,
личные данные, другое). Одна жалоба от человека; после жалоб от 3 разных людей пост уходит на проверку.

**Главное правило: модерация не прячет опасность.** У поста «на проверке» скрываются текст и фото, но сигнал
об опасности продолжает учитываться на карте — иначе конкуренты могли бы жалобами спрятать промоину.
Спокойный пост «без тревог» на проверке не учитывается, пока модератор его не одобрит.

**Модератор** видит в профиле кнопку «Модерация»: очередь постов на проверке и с жалобами, причины, автора.
Действия: одобрить, скрыть, скрыть и заблокировать автора на 7 дней, удалить. Каждое решение пишется в
журнал (`moderation_actions`). Заблокированный может смотреть карту, но не публиковать.

Роли назначаются только на сервере, через приложение их получить нельзя:

```powershell
.venv\Scripts\python -m app.admin role ivan@mail.ru moderator
```

```powershell
.venv\Scripts\python -m app.admin staff
```

```powershell
.venv\Scripts\python -m app.admin unban ivan@mail.ru
```

```powershell
.venv\Scripts\python -m app.admin log
```

## Защита от дурака (неверный ввод)

Приложение не падает и не молчит на неправильном вводе: каждая ошибка объясняется по-русски, у поля.

- **На телефоне** (`mobile/src/lib/validate.ts`) поля проверяются, пока человек печатает: email (нет @,
  кириллица, опечатки вида `gmail.con`, `mail.ry` с кнопкой «Исправить»), пароль (длина, буквы и цифры,
  слишком простой, содержит email или имя), повтор пароля, кнопка «Показать пароль», имя (2–40 символов,
  без ссылок, без служебных имён вроде «Админ» или «МЧС»). Толщина льда — только число 0–150.
- **На сервере** (`backend/app/auth.py`, `backend/app/errors.py`) те же правила проверяются ещё раз.
  Технические ошибки FastAPI переводятся в понятные фразы: «Толщина льда: нужно целое число»,
  «Что вы видите: выберите вариант из списка», «Период: должно быть не меньше 1». Пробелы и регистр в email
  исправляются сами. Повреждённый запрос, пустой или битый файл фото, огромный номер наблюдения,
  бесконечность вместо числа — всё это даёт понятный ответ 4xx, а не падение сервера.
- **От ботов** (человек этого не видит): скрытое поле-ловушка `website`, не больше 3 регистраций с IP в час
  и 10 в сутки, запрет одноразовых почтовых ящиков; после 10 неверных паролей к одному email или 30 с одного IP
  за 15 минут вход блокируется на 15 минут.

## Защита от перегрузки и DDoS

**В приложении** (`backend/app/protection.py`, `backend/app/db.py`):

| Мера | Значение |
|---|---|
| Лимит запросов на IP | вход и регистрация: 5 в минуту; фото: 6 в минуту; запись: 30 в минуту; чтение: 5 в секунду, всплеск до 60 |
| Кэш тяжёлых ответов | `/status`, `/alerts`, `/clusters` — 20 секунд, сброс при каждой записи |
| Пул соединений MySQL | 10 + 5; при переполнении ждём 5 с и отвечаем 503, а не открываем сотни соединений |
| Время одного запроса | 3 с (MySQL `max_execution_time`, MariaDB `max_statement_time`) |
| Размер запроса | до 9 МБ |
| Обработка фото | не больше 2 одновременно, в отдельном потоке |
| Выборки | не больше 5000 строк за запрос, ленты — не больше 200 |

**В MySQL** (`backend/sql/mysql_setup.sql`, `backend/sql/my.cnf.example`): отдельный пользователь
только с localhost и только с правами на свою базу, `MAX_USER_CONNECTIONS 30`, лимиты запросов в час,
`bind-address = 127.0.0.1` (базу не видно из интернета), `max_connections`, `wait_timeout`,
`max_connect_errors`, журнал медленных запросов.

**Чего приложение сделать не может:** остановить DDoS, который забивает сам канал сервера. Для этого
нужен фильтр перед сервером: Cloudflare (бесплатный тариф), DDoS-Guard или защита хостинга. Лимиты
хранятся в памяти одного процесса: при нескольких воркерах uvicorn у каждого свои счётчики.

### Monkey testing (тест на дурака) — `backend/tests/test_monkey.py`

Проверяет, что никакой ввод не роняет сервер (нет ответа 500):

- **dumb monkey** — ничего не знает об API: случайные адреса, параметры, заголовки и тела запросов ко всем
  маршрутам (мусорные байты, обрезанный JSON, `"; DROP TABLE users; --`, `<script>`, `../../etc/passwd`,
  эмодзи, нулевые байты, строки по 10 000 символов, огромные и отрицательные числа, NaN, бесконечность);
- **smart monkey** — знает, как устроены запросы: берёт правильные данные регистрации, входа, наблюдения
  и реакции и ломает по 1–3 поля; каждая ошибка 422 обязана содержать понятный текст;
- **photo monkey** — пустой файл, обрезанный JPEG, GIF, PDF, SVG, картинка 1×1, очень широкая,
  чёрно-белая, с прозрачностью и случайные байты.

Генератор случайных чисел с зерном: упавший прогон можно повторить. Длинный прогон:

```powershell
$env:MONKEY_SEED=7; $env:MONKEY_N=3000; .venv\Scripts\python -m pytest tests\test_monkey.py -q
```

Эти тесты уже нашли и помогли исправить три ошибки: пустой файл фото ронял OpenCV, номер наблюдения
из 100 цифр не помещался в базу, а точность GPS `1e309` (бесконечность) ломала запись в MySQL.

### Monkey testing интерфейса на Android

У Android есть стандартный инструмент UI/Application Exerciser Monkey: он сам нажимает, листает и вводит
случайные данные. Нужны Android-телефон с включённой «Отладкой по USB» и `adb` (Android SDK Platform-Tools).
Откройте приложение в Expo Go, затем:

```powershell
adb shell monkey -p host.exp.exponent --pct-syskeys 0 --throttle 150 -s 42 -v 1500
```

`-p` ограничивает обезьяну приложением Expo Go, `-s 42` — зерно для повтора, `--pct-syskeys 0` — без кнопок
«Домой» и громкости. Если приложение упадёт, в выводе будет `// CRASH`.
