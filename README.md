# Крепкий лёд



Карта состояния льда в заливах у Владивостока: наблюдения рыбаков, погода, запреты МЧС и предупреждения ИИ.
Приложение не гарантирует безопасность льда и не оценивает его прочность.

| Компонент | Технология |
|---|---|
| Мобильное приложение | React Native + Expo (SDK 58), Expo Router, TypeScript |
| Карта | react-native-maps: Apple Maps на iOS, Google Maps на Android, по желанию подложка OpenStreetMap |
| Геоданные | GeoJSON: `backend/data/zones.geojson` |
| Backend | Python + FastAPI |
| БД | SQLite через SQLAlchemy (переход на PostgreSQL: сменить `DATABASE_URL`) |
| ИИ | Ollama + локальная LLM (по умолчанию `qwen2.5:3b`), запасной вариант — классификатор на правилах |
| Погода | Open-Meteo (без ключа), кэш 30 минут, при недоступности — демо-значения с пометкой |

## Запуск

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m app.seed               # демо-наблюдения (необязательно)
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Документация API: http://localhost:8000/docs. Тесты: `pytest -q`.

### 2. Локальная LLM (необязательно)

```bash
ollama pull qwen2.5:3b
ollama serve
```

Если Ollama не запущена или не отвечает за 8 секунд, сервер сам использует правила. Модель задаётся
переменными `OLLAMA_URL` и `OLLAMA_MODEL`. `KL_DISABLE_LLM=1` отключает LLM, `KL_OFFLINE=1` отключает
и LLM, и Open-Meteo.

### 3. Мобильное приложение

```bash
cd mobile
npm install
cp .env.example .env             # впишите IP компьютера в EXPO_PUBLIC_API_URL
npx expo start
```

Откройте QR-код в Expo Go (Android или iOS). Телефон и компьютер должны быть в одной Wi-Fi сети.

## Карта

Используется настоящая карта, а не рисунок: `react-native-maps` с полигонами участков из GeoJSON.

- **Expo Go**: работает сразу, ключи не нужны.
- **Собственная сборка** (`eas build` или `npx expo prebuild`): на Android нужен ключ Google Maps SDK
  в `GOOGLE_MAPS_ANDROID_KEY`. iOS использует Apple Maps без ключа.
- **Без Google**: `EXPO_PUBLIC_MAP_TILES=osm` рисует подложку OpenStreetMap. Для продакшена нужен свой
  тайл-сервер или коммерческий провайдер: публичные тайлы OSM не рассчитаны на нагрузку приложения.

Участки задаются в `backend/data/zones.geojson` (Polygon, координаты `[lon, lat]`). Сейчас там шесть
шестиугольников вокруг приблизительных точек: Седанка, Де-Фриз, Угловое, Шамора, Патрокл, Суходол.
Перед релизом нарисуйте настоящие контуры (geojson.io или QGIS) и сверьте с местными спасателями
сектора отжимного ветра (`offshore_from`). Запрет у Патрокла — пример, а не реальные данные МЧС.
Сервер перечитывает файл при каждом старте.

## Правила статуса (`backend/app/status.py`)

- Шкала без «безопасно»: Опасно → Есть риск → Тревог нет → Нет данных (серый пунктир).
- Одно свежее сообщение об опасности важнее любого числа сообщений «всё нормально».
- Наблюдение свежее 6 часов, в оттепель и при ветре от 10 м/с — 3 часа. Через 24 часа не учитывается.
- Отжимной ветер от 8 м/с поднимает участок минимум до «Есть риск».
- ИИ и погода только повышают уровень, никогда не понижают.
- Официальный запрет всегда даёт «Опасно».
- Наблюдение, которое чаще отмечают «Неверно», чем «Подтверждаю» (минимум 2 голоса), не учитывается.

## Защита данных

- «На месте» ставится, только если GPS в пределах 300 м от участка, точность до 50 м и геолокация не подменена.
- Подтвердить можно только в пределах 2 км от участка. Свои наблюдения оценивать нельзя.
- Не больше 10 публикаций в час с одного устройства.
- Фото только с камеры, до 5 МБ.
- Точка в постах без тревог загрубляется до квадрата 200 м, точка опасности остаётся точной.
- Наблюдения без сети сохраняются на телефоне с исходным временем и отправляются при появлении связи.
  Старше суток сервер не принимает.
